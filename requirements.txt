# Workflow uv (uv est l'outil, ce fichier reste le format et la verite)
# ---------------------------------------------------------------------------
#   uv venv                                 une seule fois, cree .venv
#   uv pip install -r requirements.txt      synchroniser (ex. apres un git pull)
#
#   `uv venv` CREE l'environnement, il ne l'ACTIVE pas - aucune commande ne
#   peut activer un venv depuis un sous-processus. Avec `uv run` ci-dessous,
#   l'activation est inutile : uv prend .venv tout seul. Si vous voulez quand
#   meme un prompt active :  source .venv/bin/activate   (Windows Git Bash :
#   source .venv/Scripts/activate). Et si .venv existe deja, `uv venv` refuse
#   de l'ecraser : passez simplement a la ligne suivante.
#
#   uv run python run_model.py --model train --input dataset  --output-dir output
#   uv run python run_model.py --model test  --input sample_input.csv --output-dir output
#
#   Ajouter une dependance = DEUX gestes :
#     uv pip install scikit-learn           1. installer dans .venv
#     scikit-learn>=1.3                     2. ajouter la ligne ici, a la main
#
#   ./scripts/check_env.sh 3.11 3.12        filet de securite : env neuf par
#     version de Python, bati depuis ce seul fichier, verifie que tout import
#     de my_model/ s'y resout, puis lance validate_submission.py. A lancer
#     avant chaque commit et avant la soumission.
#
#   NE PAS utiliser `uv add` : cela cree un pyproject.toml concurrent, donc une
#   seconde liste de dependances qui derivera de celle-ci. Les organisateurs
#   n'installent que requirements.txt.
#
#   Versions : planchers larges sur les paquets de base (la version de Python
#   des organisateurs n'est pas publiee, c'est un <<TODO>> des instructions),
#   epingler surtout les paquets lourds (torch, ...) une fois le modele fige.
# ---------------------------------------------------------------------------
